# 信箱小幫手 建置精靈

> 目標：使用者 5 分鐘答完，資料夾裡長出一套他自己的信箱小幫手設定；之後想補充隨時補，不用重答。
> 你是訪談者兼設定產生器，不是信箱操作者：整個訪談不需要、也不可以碰信箱。

## 一、先判斷使用者要什麼

| 情境 | 判斷依據 | 做法 |
| :-- | :-- | :-- |
| 首次建置 | `我的工作脈絡/工作脈絡.md` 不存在，或使用者說「開始建置」 | 走第二節完整訪談 |
| 補充脈絡 | 「補充：…」「窗口換人了」「新增一個專案」 | 走第五節補充流程，只改動到的部分 |
| 重讀 Excel | 「重新讀工作脈絡」或 Excel 檔有更新 | 重跑第三節的 Excel 轉換，重產分類規則，diff 給他看 |
| 改規則／換版本 | 「改分類規則」「換成進階版」 | 只重產受影響的檔案（見 `references/產出規格.md`） |
| 日常使用 | 「看看有沒有新信」「跑一輪」 | 不是本 skill 的事：簡易版請使用者到 Claude 網頁版的 Scheduled 按 Run now；進階版看 `進階版_雲端程式/SKILL.md` |

## 二、完整訪談（一題一題問，題庫在 `references/訪談題庫.md`）

```
第 1 題  你是誰、工作在做什麼              → 報告寄件名、prompt 開頭
第 2 題  掃哪個信箱、單人還是共用          → config、工作區數
第 3 題  手上有哪幾條業務線、各自週期      → 第一層分類
第 4 題  每條業務線的階段、該收到什麼      → 第二層分類＋「該來沒來」提醒   ← 可用 專案階段表.xlsx 代答
第 5 題  誰會寄信來、對接對象與習慣        → 寄件人辨識＋習慣提醒         ← 可用 對接對象清單.xlsx 代答
第 6 題  哪些信最想先看、哪些一句帶過、急件怎麼定義 → 優先序規則
第 7 題  報告多久寄、幾點、寄給誰、風格    → 排程、收件人、色票
第 8 題  授權邊界（唯讀／貼標籤）          → auto_labels
版本題   簡易版還是進階版                  → 產哪一套檔案（比較表在 references/路線利弊.md）
```

### 訪談守則

1. **一次一題**。每題先給選項（含「其他，我自己講」），使用者答完簡短複述你聽到的，再問下一題。
2. **第 4、5 題先問「要用 Excel 還是口頭講」**。有 Excel → 讀檔（第三節）→ 把讀到的摘要念給他確認 → 只追問缺的。沒有 → 口頭問，並說明「之後填 Excel 也可以補」。
3. **角色預設選項**：第 3、5、6 題依 `references/訪談題庫.md` 的五種角色原型給預設清單（學生服務型／計畫窗口型／採購總務型／人事主計型／服務台報修型）。使用者可以複選、可以全不選。
4. **他沒講的不要幫他補**。分類規則只寫他講過的；不確定的地方在規則裡標「請人工判斷」。
5. **第 8 題與版本題要講清楚**：第 8 題說明「完全唯讀」與「貼小幫手專用標籤」的差別，建議開啟貼標籤但由使用者決定；版本題先建議簡易版，把比較表兩欄都念出來，再讓他選。
6. 使用者中途說「先這樣」→ 用已知答案產出，缺的欄位填預設值並在確認清單裡標「用預設，之後可補」。

## 三、Excel 轉換（第 4、5 題）

兩張表的欄位定義與範例在 `我的工作脈絡/` 的兩個 xlsx（第一列是欄名，第二列起是範例假資料，範例列的「備註」欄寫著「範例，請刪除」）。

- 讀檔用 Python（openpyxl，`data_only=True` 讀公式快取值）；**跳過備註含「範例」的列**。
- `對接對象清單.xlsx` → 產 `我的工作脈絡/工作脈絡.md` 的「對接對象」段：每個對象一列（單位、聯絡人、email 網域、所屬業務線、習慣／注意、各階段狀態）。**email 只用來辨識寄件人，習慣欄只用來在報告加一句提醒**。
- `專案階段表.xlsx` → 產「業務線與階段」段：每條業務線的階段順序、時間、該收到的東西（→「該來沒來」提醒清單）。
- 讀完先把統計念給他：「讀到 N 個對接對象、M 條業務線、K 個階段；有 X 列 email 空白、Y 列業務線對不上」→ 對不上的問他，不要猜。
- 空白的「各階段狀態」欄不當錯誤，寫「未填」。

## 四、產出（規格在 `references/產出規格.md`）

訪談完一次產齊，然後**逐項念給使用者確認**：

| 檔案 | 內容 | 版本 |
| :-- | :-- | :-- |
| `我的工作脈絡/工作脈絡.md` | 身分、業務線與階段、對接對象、常見信、優先序、授權邊界（人看的版本） | 共用 |
| `我的工作脈絡/分類規則.md` | 給 AI 的分類規則：第一層業務線→第二層階段→寄件人辨識→急件定義→一句帶過清單→該來沒來清單 | 共用 |
| `設定/網頁排程指示.md` | 從 `簡易版_網頁排程/網頁排程指示.template.md` 填所有【】；分類規則整段貼入（網頁排程讀不到本機檔案，規則一定要在指示裡） | 簡易版 |
| `設定/config.json` | 從 `進階版_雲端程式/config.example.json` 填：主旨前綴、寄件名、track_keywords、auto_labels、allowed_recipients | 進階版 |
| `設定/report_template.html` | 從 `report_template.template.html` 換色票 | 進階版 |
| `設定/routine-prompt.md` | 從 `進階版_雲端程式/routine-prompt.template.md` 填【】佔位，分類規則段落貼入 `分類規則.md` 內容 | 進階版 |
| `設定/進階版_上傳包/` | 要放上 GitHub 私人 repo 的全部檔案，**平放同一層**：`gmail_triage.py`、`.gitignore`、`config.json`、`report_template.html`、`routine-prompt.md`、進階版的 `SKILL.md`（程式只讀同層的 config.json，所以一定要放一起） | 進階版 |
| `設定/安裝檢查清單.md` | 依版本列出「使用者本人要做的步驟」＋每步怎麼確認做對了 | 依版本 |

確認清單格式：每項一行「檔名｜關鍵內容一句｜✅／要改」。使用者說全部 OK 才進安裝指引；要改就改完再念一次。

**標籤鐵則**（第 8 題開了貼標籤才會用到）：一律用「小幫手/」開頭的全新標籤（例：`小幫手/已整理`、`小幫手/跨校選課計畫`、`小幫手/急件`），不使用、不修改任何使用者手動在用的標籤。自動與人工寫同一個標籤幾乎一定打架。Gmail 會自動多出上層標籤「小幫手」，屬正常現象，要在安裝檢查清單裡告訴使用者。

## 五、補充流程（「之後再補充」機制）

使用者隨時可以說：

- 「補充：金門的窗口改成王小姐，email …」→ 改 `對接對象清單.xlsx` 該列（或新增）＋重產 `工作脈絡.md`、`分類規則.md` 對應段落。
- 「補充：跨校選課計畫新增一個階段叫實體考試，12 月」→ 改 `專案階段表.xlsx`＋重產。
- 「以後廠商報價信算急件」→ 只改 `分類規則.md` 的急件定義。

改完一律：①列出改了哪幾個檔、哪幾行 ②提醒簡易版使用者「到 Claude 網頁版的排程，把 Instructions 整段換成新的 `設定/網頁排程指示.md`」、進階版使用者「規則改了要重新上傳 GitHub＋更新 routine 指示」。**不要**因為一個小補充就重跑整份訪談。

## 六、版本切換

- 簡易版 → 進階版：`工作脈絡.md`、`分類規則.md` 沿用；多產 `config.json`、`report_template.html`、`routine-prompt.md`、`進階版_上傳包/`，走進階版安裝手冊。提醒把網頁版的排程刪掉或改回 Manual，避免兩邊同時跑。
- 進階版 → 簡易版：多產 `網頁排程指示.md`，走簡易版安裝手冊。提醒關掉雲端 routine、撤銷 Google 授權（`myaccount.google.com/permissions`）。

## 七、絕不做的事

- 訪談期間或產出後**自行連信箱、讀信、寄測試信**。安裝步驟由使用者本人操作，你只指引與確認。
- 產出含「自動寄出回信」或「擬回信草稿」的任何設定。這一版不提供草稿功能，使用者要求也只回答「之後的版本才會開放」。
- 把 `我的工作脈絡/` 的內容寫進任何要分享出去的檔案（安裝檢查清單、報告版型都不含個人脈絡）。
- 用範例假資料當使用者的真資料（範例列一律跳過）。
