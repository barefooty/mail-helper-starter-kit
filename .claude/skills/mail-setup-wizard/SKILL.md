# 信箱小幫手 建置精靈

> 目標：使用者 5 分鐘答完（或領問卷慢慢填），資料夾裡長出一套他自己的信箱小幫手設定；之後想補充隨時補，不用重答。
> 你是訪談者兼設定產生器，不是信箱操作者。唯一會碰信箱的時刻是第 0 題使用者**明確同意**的「唯讀側寫」（只統計寄件人與主旨樣式，規格在 `references/信箱側寫規格.md`）；其餘時間不需要、也不可以碰信箱。

## 一、先判斷使用者要什麼

| 情境 | 判斷依據 | 做法 |
| :-- | :-- | :-- |
| 首次建置 | `我的工作脈絡/工作脈絡.md` 不存在，或使用者說「開始建置」 | 先問第 0 題（第二節），再走完整訪談 |
| 先掃信箱 | 「先掃信箱」「幫我看過去一週的信」 | 走第 2b 節側寫流程，掃完回到第 1 題 |
| 讀側寫 | 「讀側寫」或 `我的工作脈絡/信箱側寫.md` 剛出現 | 讀檔→念統計摘要→用側寫預填第 3、5、6 題的選項 |
| 領問卷 | 「給我問卷」「我想慢慢填」 | 走第 2c 節：產 `我的工作脈絡/工作脈絡問卷.docx`（有側寫就預填），告訴他填完怎麼交回 |
| 讀問卷 | 「讀問卷」「我填好了」或問卷檔有更新／使用者上傳了 .docx | 走第 2c 節讀回流程：只追問空白與矛盾，不重跑訪談 |
| 補充脈絡 | 「補充：…」「窗口換人了」「新增一個專案」 | 走第五節補充流程，只改動到的部分 |
| 重讀 Excel | 「重新讀工作脈絡」或 Excel 檔有更新 | 重跑第三節的 Excel 轉換，重產分類規則，diff 給他看 |
| 改規則／換版本 | 「改分類規則」「換成進階版」 | 只重產受影響的檔案（見 `references/產出規格.md`） |
| 日常使用 | 「看看有沒有新信」「跑一輪」 | 不是本 skill 的事：簡易版請使用者到 Claude 網頁版的 Scheduled 按 Run now；進階版看 `進階版_雲端程式/SKILL.md` |

## 二、完整訪談（一題一題問，題庫在 `references/訪談題庫.md`）

```
第 0 題  怎麼答：直接聊／先掃信箱再聊／領 Word 問卷慢慢填  → 決定走 2a／2b／2c
第 1 題  你是誰、工作在做什麼              → 報告寄件名、prompt 開頭
第 2 題  掃哪個信箱、單人還是共用          → config、工作區數
第 3 題  手上有哪幾條業務線、各自週期      → 第一層分類
第 4 題  每條業務線的階段、該收到什麼      → 第二層分類＋「該來沒來」提醒   ← 可用 專案階段表.xlsx 代答
第 5 題  誰會寄信來、對接對象與習慣        → 寄件人辨識＋習慣提醒         ← 可用 對接對象清單.xlsx 代答
第 6 題  哪些信最想先看、哪些一句帶過、急件怎麼定義 → 優先序規則
第 7 題  報告多久寄、幾點、寄給誰、風格    → 排程、收件人、色票
第 8 題  授權邊界（唯讀／貼標籤）          → auto_labels
         ＋子選項：敏感類別只列不摘要（預設不開；列法＝王O明（學校）｜主旨｜時間，學號打碼）→ 分類規則「敏感類別清單」；打碼兩版固定做、不用問
版本題   簡易版還是進階版                  → 產哪一套檔案（比較表在 references/路線利弊.md）
```

### 訪談守則

0. **先講地圖，再開始；每題報進度與目的**（2026-10-19 使用者測試回饋：不知道步驟在幹嘛就被問，很慌）。開場照 `CLAUDE.md` 的 4 步地圖講（訪談→念產出→連信箱建排程→手動跑一次）。每題開頭固定格式：「**第 N／8 題｜主題**。問這個是為了＿＿（題庫每題的「為什麼問」，照念）。」答完複述時順便說「這會變成報告的＿＿」。訪談結束說：「訪談結束。接下來我念 N 個檔給你確認（約 3 分鐘），然後進安裝 4 步。」念產出、安裝每步也都先報「現在第幾步、這步是為了什麼」。
1. **一次一題**。每題先給選項（含「其他，我自己講」），使用者答完簡短複述你聽到的，再問下一題。
2. **第 4、5 題先問「要用 Excel 還是口頭講」**。有 Excel → 讀檔（第三節）→ 把讀到的摘要念給他確認 → 只追問缺的。沒有 → 口頭問，並說明「之後填 Excel 也可以補」。
3. **角色預設選項**：第 3、5、6 題依 `references/訪談題庫.md` 的五種角色原型給預設清單（學生服務型／計畫窗口型／採購總務型／人事主計型／服務台報修型）。使用者可以複選、可以全不選。
4. **他沒講的不要幫他補**。分類規則只寫他講過的；不確定的地方在規則裡標「請人工判斷」。
5. **第 8 題與版本題要講清楚**：第 8 題說明「完全唯讀」與「貼小幫手專用標籤」的差別，建議開啟貼標籤但由使用者決定；答完順帶問子選項「有沒有哪類信（人事、主計、學生個資）敏感到連摘要都不要出現」，預設不開。打碼（身分證／電話／10 碼以上數字／帳密值換「○」）不用問、兩版固定做，只講一句限制：指示層靠模型自律、程式層只遮已知樣式。版本題先建議簡易版，把比較表兩欄都念出來，再讓他選。
6. 使用者中途說「先這樣」→ 用已知答案產出，缺的欄位填預設值並在確認清單裡標「用預設，之後可補」。
7. **有側寫就先念側寫**：第 3、5、6 題先把 `信箱側寫.md` 第 6 節的候選念成選項（標明「這是從信裡看到的，對嗎？」），再附角色原型的預設清單。使用者否決的候選不再出現。

### 2a｜直接聊（現行）
照上面的順序一題一題問。

### 2b｜先掃信箱（側寫）
1. 照 `references/信箱側寫規格.md` 第一節**念同意詞**：只讀寄件人、主旨、日期、附件有無；不讀內文、不改任何東西。使用者沒點頭就不掃。
2. **檢查這個對話有沒有 Gmail 連接器工具**（`search_threads`、`get_thread`、`list_labels` 之類）。這些工具常在「延遲載入」清單裡只有名字，**先用 ToolSearch 查 `search_threads`**，查得到就載入；只看已載入的工具會誤判成沒有：
   - 有 → 路徑 A，照規格第三節當場掃（snippet 視同內文；只用 MINIMAL／METADATA_ONLY；上限 150 串），產 `我的工作脈絡/信箱側寫.md`。
   - 真的沒有 → 路徑 B，請使用者到 claude.ai 貼 `我的工作脈絡/信箱側寫_網頁版預掃指示.md` 的「指示全文」，把回覆存成 `我的工作脈絡/信箱側寫.md` 後說「讀側寫」。**不要叫他重開 app 碰運氣，直接走 B。**
   - 掃之前提醒：若信箱裡正在跑測試中的小幫手排程，先停掉，不然它自己的報告會污染側寫。
3. 掃完或讀完，先念三行摘要（共幾封、前三大來源、系統通知占比），再進第 1 題。
4. 側寫掃完就不再碰信箱。側寫檔保留不刪，它同時是「用小幫手之前」的基準數字；它是真實資料，起始包的 `.gitignore` 已排除，分享起始包時也不要帶上。

### 2c｜Word 問卷（慢慢填）
適合第 3、4、5 題要查資料、問同事、想一想的人。問卷涵蓋第 1 到 8 題與版本題；必答題紅字加黃框，選填題灰字；答案片段即可，精靈會潤飾。

**產問卷**：
```
python .claude/skills/mail-setup-wizard/scripts/make_questionnaire.py --out 我的工作脈絡/工作脈絡問卷.docx [--prefill <預填.json>]
```
- 有 `信箱側寫.md` → 先把側寫第 6 節整理成預填 JSON（格式見 `references/產出規格.md` 第 0b 項），用 `--prefill` 產「預填版」，使用者是在勾選與修正，不是從空白開始。
- 產完告訴他三件事：①檔在哪 ②填完放回 `我的工作脈絡/`（Cowork／網頁版就直接上傳）③回來說「讀問卷」。順便提醒：第 4、5 題超過 10 列的人改填兩張 Excel，問卷那兩題留空即可。

**讀問卷**：
```
python .claude/skills/mail-setup-wizard/scripts/read_questionnaire.py 我的工作脈絡/工作脈絡問卷.docx
```
- 腳本依「Q1｜…」標題切題，輸出 Markdown；空白格印「（未填）」，勾選格認 ☑／■／✓／V／是。
- 讀完先念「讀到 N 題有答案、M 題空白、K 處對不上（例：第 5 題的業務線名稱在第 3 題沒出現）」，**只追問空白的必答題與矛盾處**，不重跑整份訪談。選填題空白就用預設，確認清單標「用預設，之後可補」。
- 問卷與 Excel 都有填時：Excel 為準、問卷補漏；問卷填的內容與對話裡講的衝突時，以**較晚**的為準並複述確認。

## 三、Excel 轉換（第 4、5 題）

兩張表的欄位定義與範例在 `我的工作脈絡/` 的兩個 xlsx（第一列是欄名，第二列起是範例假資料，範例列的「備註」欄寫著「範例，請刪除」）。

- 讀檔用 Python（openpyxl，`data_only=True` 讀公式快取值）；**跳過備註含「範例」的列**。
- `對接對象清單.xlsx` → 產 `我的工作脈絡/工作脈絡.md` 的「對接對象」段：每個對象一列（單位、聯絡人、email 網域、所屬業務線、習慣／注意、各階段狀態）。**email 只用來辨識寄件人，習慣欄只用來在報告加一句提醒**。
- `專案階段表.xlsx` → 產「業務線與階段」段：每條業務線的階段順序、時間、該收到的東西（→「該來沒來」提醒清單）。
- 讀完先把統計念給他：「讀到 N 個對接對象、M 條業務線、K 個階段；有 X 列 email 空白、Y 列業務線對不上」→ 對不上的問他，不要猜。
- 空白的「各階段狀態」欄不當錯誤，寫「未填」。

## 四、產出（規格在 `references/產出規格.md`）

訪談完一次產齊，然後**逐項念給使用者確認**：

| 檔案 | 內容 | 版本 |
| :-- | :-- | :-- |
| `我的工作脈絡/信箱側寫.md`（選掃才有） | 過去 7／30 天的寄件網域、主旨樣式、系統通知、量與節奏；只有統計 | 共用 |
| `我的工作脈絡/工作脈絡問卷.docx`（選問卷才有） | 使用者填的問卷正本；讀回後保留，不改寫 | 共用 |
| `我的工作脈絡/工作脈絡.md` | 身分、業務線與階段、對接對象、常見信、優先序、授權邊界（人看的版本）；檔頭「來源」要寫明訪談／側寫／問卷／Excel 各用了哪些 | 共用 |
| `我的工作脈絡/分類規則.md` | 給 AI 的分類規則：第一層業務線→第二層階段→寄件人辨識→急件定義→一句帶過清單→該來沒來清單→敏感類別清單（第 8 題子選項；沒開寫「無」，但打碼那一行固定在） | 共用 |
| `設定/網頁排程指示.md` | 從 `簡易版_網頁排程/網頁排程指示.template.md` 填所有【】；分類規則整段貼入（網頁排程讀不到本機檔案，規則一定要在指示裡）；「報告版型」段的頁首色／分隔線色依第 7 題 preset 填入（報告用 Gmail 連接器 htmlBody 寄 HTML 信） | 簡易版 |
| `設定/config.json` | 從 `進階版_雲端程式/config.example.json` 填：主旨前綴、寄件名、track_keywords、auto_labels、allowed_recipients；`mask_sensitive` 維持 true | 進階版 |
| `設定/report_template.html` | 從 `report_template.template.html` 換色票 | 進階版 |
| `設定/routine-prompt.md` | 從 `進階版_雲端程式/routine-prompt.template.md` 填【】佔位，分類規則段落貼入 `分類規則.md` 內容 | 進階版 |
| `設定/進階版_上傳包/` | 要放上 GitHub 私人 repo 的全部檔案，**平放同一層**：`gmail_triage.py`、`.gitignore`、`config.json`、`report_template.html`、`routine-prompt.md`、進階版的 `SKILL.md`（程式只讀同層的 config.json，所以一定要放一起） | 進階版 |
| `設定/安裝檢查清單.md` | 依版本列出「使用者本人要做的步驟」＋每步怎麼確認做對了 | 依版本 |

確認清單格式：每項一行「檔名｜關鍵內容一句｜✅／要改」。使用者說全部 OK 才進安裝指引；要改就改完再念一次。

**安裝指引（簡易版）先問一句**：「安裝步驟要自己做，還是讓我在 Chrome 裡替你點？」選「替我點」→ 先確認他裝好 Claude in Chrome 擴充功能並綁定自己的帳號（指到 `說明圖/Claude擴充功能_安裝與綁定.png`，8 步），之後他說「幫我做安裝步驟」時，你用瀏覽器工具在 claude.ai 替他做手冊步驟 1、3、4（Connectors 按「＋」、Scheduled 建排程貼指示、Run now、改定時）。**遇到 Google 登入、選帳號、「允許」畫面一律停下來說「換你操作」**；不輸入任何密碼、不替他按授權、不向他要密碼。對話裡沒有瀏覽器工具就老實說，改回「自己做」版本的檢查清單。

**標籤鐵則**（第 8 題開了貼標籤才會用到）：一律用「小幫手/」開頭的全新標籤（例：`小幫手/已整理`、`小幫手/跨校選課計畫`、`小幫手/急件`），不使用、不修改任何使用者手動在用的標籤。自動與人工寫同一個標籤幾乎一定打架。Gmail 會自動多出上層標籤「小幫手」，屬正常現象，要在安裝檢查清單裡告訴使用者。

## 五、補充流程（「之後再補充」機制）

使用者隨時可以說：

- 「補充：金門的窗口改成王小姐，email …」→ 改 `對接對象清單.xlsx` 該列（或新增）＋重產 `工作脈絡.md`、`分類規則.md` 對應段落。
- 「補充：跨校選課計畫新增一個階段叫實體考試，12 月」→ 改 `專案階段表.xlsx`＋重產。
- 「以後廠商報價信算急件」→ 只改 `分類規則.md` 的急件定義。

改完一律：①列出改了哪幾個檔、哪幾行 ②提醒簡易版使用者「到 Claude 網頁版的排程，把 Instructions 整段換成新的 `設定/網頁排程指示.md`」、進階版使用者「規則改了要重新上傳 GitHub＋更新 routine 指示」。**不要**因為一個小補充就重跑整份訪談。

## 六、版本切換

- 簡易版 → 進階版：`工作脈絡.md`、`分類規則.md` 沿用；多產 `config.json`、`report_template.html`、`routine-prompt.md`、`進階版_上傳包/`，走進階版安裝手冊。提醒把網頁版的排程刪掉或改回 Manual，避免兩邊同時跑。
- 進階版 → 簡易版：多產 `網頁排程指示.md`，走簡易版安裝手冊。提醒關掉雲端 routine、撤銷 Google 授權（`myaccount.google.com/permissions`）。

## 七、絕不做的事

- 訪談期間或產出後**自行連信箱、讀信、寄測試信**。唯一例外是第 0 題使用者明確同意的唯讀側寫，且只做 `references/信箱側寫規格.md` 第三節允許的事（讀寄件人、主旨、日期、附件有無、標籤名；不讀內文、不寫入）。安裝步驟由使用者本人操作，你只指引與確認；唯一例外是他明確選「替我點」且對話裡有瀏覽器工具，你才替他操作 claude.ai 的 Connectors 與 Scheduled 頁，登入與授權仍由他本人做（見第四節「安裝指引先問一句」）。
- 把信件內文、完整 email 地址、個人姓名寫進 `信箱側寫.md` 或任何產出；未經同意掃信箱；使用者否決的側寫候選再拿出來問。
