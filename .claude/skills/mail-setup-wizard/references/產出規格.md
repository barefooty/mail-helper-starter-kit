# 產出規格（訪談後要長出的每個檔案）

> 所有檔案用繁體中文（使用者指定別的語言就照他的）。範例假資料一律不得進入產出。

## 0. `我的工作脈絡/信箱側寫.md`（第 0 題選「先掃信箱」才有）

格式與去識別規則全部照 `信箱側寫規格.md` 第三、四節。只有統計：網域、主旨樣式、封數、系統通知來源、量與節奏、現有標籤、預填候選。**不得出現**信件內文、完整 email 地址（網域以外的部分）、個人姓名。檔頭寫掃描時間、範圍、方式（當場掃／網頁版預掃）、是否截斷。

## 0b. `我的工作脈絡/工作脈絡問卷.docx`（第 0 題選「問卷」才有）

由 `scripts/make_questionnaire.py` 產生，不手刻。版面規則：必答題標題紅字、答案框淡黃底；選填題標題灰字、答案框淡灰底；第 4、5 題用表格（8 列，超過請改填 Excel）；全文微軟正黑體；第一頁有「怎麼填」三行說明。

預填 JSON（`--prefill`）格式，鍵都可省略：

```json
{
  "source": "信箱側寫 2026-10-16（過去 7 天）",
  "q3_lines":   ["跨校選課計畫", "暑期課程", "經費核銷"],
  "q5_rows":    [{"單位": "甲大學 通識教育中心", "聯絡人": "", "email或網域": "example-a.edu.tw", "業務線": "跨校選課計畫", "習慣／注意": ""}],
  "q6_skip":    ["Google 表單回覆通知", "平台系統通知"],
  "q6_urgent":  ["主旨含「截止」「催」「退件」"]
}
```

預填的列與選項會標「側寫預填，請確認或修改」；使用者刪掉或改掉的就以問卷為準。問卷讀回用 `scripts/read_questionnaire.py`，輸出 Markdown 給精靈判讀；問卷檔本身讀回後保留、不改寫。

## 1. `我的工作脈絡/工作脈絡.md`（人看的）

```
# ○○的工作脈絡（信箱小幫手用）
> 最後更新：YYYY-MM-DD｜來源：訪談＋問卷（YYYY-MM-DD）＋信箱側寫（過去 7 天）＋對接對象清單.xlsx＋專案階段表.xlsx（有用到的才寫）

## 我是誰
職稱／單位／工作一句話／角色原型（A–E，可複數）

## 信箱
掃描信箱／單人或共用（共用列分工）／報告收件人／報告時間

## 業務線與階段
每條線一張表：階段｜大約時間｜該收到什麼｜來自誰｜最容易出事的點

## 對接對象
表：單位｜聯絡人｜email 網域｜所屬業務線｜習慣／注意｜各階段目前狀態（未填寫「未填」）

## 信的優先序
最先看／一句帶過／急件定義

## 授權邊界
唯讀｜貼標籤（清單）；選的版本

## 之後想補充
（留空，提示他怎麼補）
```

## 2. `我的工作脈絡/分類規則.md`（給 AI 的，會整段貼進 prompt）

```
## 分類規則
### 第一層：業務線
- 【業務線 A】：寄件人屬於（對象清單）／主旨或內文含（關鍵字）→ 歸此線
- 對不上任何線 → 「其他」
### 第二層：階段（只在能判斷時標）
- 【業務線 A】／【階段 1】：關鍵字／時間窗
### 寄件人辨識
- email 或網域 → 對象名稱（單位）→ 業務線；附「習慣提醒」一句（有才寫）
### 優先序
1. 急件：（定義）
2. 還沒回覆且有期限
3. 還沒回覆
4. 已回覆／資訊
### 一句帶過
- （清單）
### 該來沒來（反向提醒）
- 【階段】【對象】應於【日期】前來信【內容】；本輪沒收到且已過期 → 報告「⏰ 該來沒來」區列出
### 敏感類別清單（第 8 題子選項；沒開就寫「- 無」）
- 【類別】：寄件人屬於（對象）／主旨含（關鍵字）→ 報告只列「寄件人｜主旨｜時間」，不寫摘要、不寫建議；姓名中間字改 O、學校照寫、學號打碼（例：王O明（甲大學）｜主旨｜時間）
- 不論有沒有開：身分證字號、手機、市話、學號、10 碼以上連續數字、「帳號／密碼：」後面的值一律換「○」
### 人工判斷
- （使用者沒定義的情況，一律寫「請人工判斷」）
```

## 3. `設定/config.json`（進階版）

從 `進階版_雲端程式/config.example.json` 複製後填值，`_` 開頭的說明鍵保留：

| 鍵 | 來源 |
| :-- | :-- |
| report_subject_prefix | 第 7 題（預設【信箱報告】；提醒不可再改） |
| sender_name | 第 1 題（預設「信箱小幫手」） |
| track_keywords | 第 8 題提醒的手動待辦標籤名（預設 ["待處理"]） |
| auto_labels | 第 8 題選 2 才 enabled=true，labels 填「前綴/類別」全新名稱 |
| allowed_recipients | 第 2、7 題 |
| overlap_minutes / default_days | 維持 15 / 5 |
| mask_sensitive | 維持 true（程式層打碼：body_preview 的身分證／電話／10 碼以上數字／帳密值換「○」）；只有使用者明說才關 |

## 4. `設定/report_template.html`（進階版）

從 `進階版_雲端程式/report_template.template.html` 複製。模板的 `{{}}` 佔位分兩類：

| 設定時就填（精靈負責） | 執行時每輪填（跑報告的 AI 負責，**保留不動**） |
| :-- | :-- |
| `{{頁首色}}` `{{分隔線色}}` `{{警示色}}`（第 7 題 preset，色碼見 `風格preset.md`） | `{{日期（週X）場次}}` `{{起訖}}` `{{今日/本週}}` `{{今日／本週}}` |
| `{{工作區名稱}}`（單人＝「○○的信箱」）`{{追蹤標籤名}}` `{{追蹤關鍵字}}` `{{寄件顯示名稱}}` `{{報告名稱}}`（＝主旨前綴） | |
| `{{標籤原則說明…}}`（唯讀版／白名單版）`{{特殊類型區塊標題…}}`（有反向提醒＝「⏰ 該來沒來」，沒有就整區刪） | |

配色鐵則：頁首色＋警示紅，其餘灰階。

## 5. `設定/routine-prompt.md`（進階版）

從 `進階版_雲端程式/routine-prompt.template.md` 填所有【】；「【分類規則】」整段用 `分類規則.md` 內容取代；「【時間與場次】」依第 7 題；cron 換算 UTC 寫在檔頭。「【報告內容原則】」的打碼條固定保留；敏感類別條只在第 8 題子選項有設定時保留，否則刪。

## 5b. `設定/進階版_上傳包/`（進階版）

`gmail_triage.py` 只讀**跟自己同一層**的 `config.json`，雲端 routine 也是在 repo 根目錄執行，所以要上傳的檔案必須平放。產完第 3～5 項後，把下列檔案複製進這個資料夾（不建子資料夾）：

| 來源 | 複製成 |
| :-- | :-- |
| `進階版_雲端程式/gmail_triage.py`、`.gitignore`、`SKILL.md` | 同名 |
| `設定/config.json`、`設定/report_template.html`、`設定/routine-prompt.md` | 同名 |

**不放**：`.env`、任何含 token 的檔案、`我的工作脈絡/` 的 Excel 與 `工作脈絡.md`（分類規則已寫進 routine-prompt.md）。`進階版_雲端程式/tests/` 是程式的單元測試，雲端用不到，可不放。每次重產設定都要同步更新上傳包，並提醒使用者重新上傳。

## 6. `設定/網頁排程指示.md`（簡易版）

從 `簡易版_網頁排程/網頁排程指示.template.md` 填所有【】，產出的檔案**不得殘留任何【】**：

| 佔位 | 來源 |
| :-- | :-- |
| 信箱主人／單位、信箱地址 | 第 1、2 題 |
| 貼標籤相關段落（「已開啟貼標籤才保留」） | 第 8 題選「貼標籤」就保留並去掉提示字；選「完全唯讀」就整段刪掉，「這次要看哪些信」改用時間窗寫法 |
| 標籤清單 | 固定有 `小幫手/已整理`、`小幫手/急件`；每條業務線一個 `小幫手/<業務線名>` |
| 報告怎麼送 | 第 7 題：寄給本人（填收件人與主旨前綴）或不寄信、直接看排程的執行紀錄 |
| 時間與場次、時間窗的 N | 第 7 題；一天多場時，每場各一個排程，指示相同、只差場次說明 |
| 分類規則 | `分類規則.md` 全文（含「敏感類別清單」段） |
| 使用者的處理原則 | 第 6 題與使用者提過的原則；沒有就寫「沒把握就寫請人工判斷」 |
| 報告內容原則的敏感類別條 | 第 8 題子選項有設定就保留並去掉提示字；沒有就刪該條。打碼條固定保留、不可刪 |

網頁排程在雲端執行，讀不到起始包資料夾。所以指示必須自成一體，不能寫「見某某檔案」。

## 7. `設定/安裝檢查清單.md`

依版本列「使用者本人要做的步驟」，每步三欄：做什麼｜怎麼確認做對了｜卡住時看哪裡。簡易版對應 `簡易版_網頁排程/安裝手冊.md` 步驟 1、3、4，並加一列說明上層標籤「小幫手」會自動出現；進階版對應 `進階版_雲端程式/安裝手冊.md` 步驟 1、3、5（上傳 `設定/進階版_上傳包/`）、6、7。

**代操作選項（簡易版）**：產清單前問一句「安裝步驟要自己做，還是讓我在 Chrome 裡替你點？」。選「替我點」→ 清單第 0 列寫「裝 Claude in Chrome 擴充功能並綁定帳號（照 `說明圖/Claude擴充功能_安裝與綁定.png`）」，步驟 1、3、4 的「做什麼」欄改寫成「對 Claude 說『幫我做安裝步驟』；跳出 Google 登入或允許畫面時由你本人操作」，「怎麼確認」欄不變。選「自己做」→ 清單照舊。代操作只用於 claude.ai 的 Connectors 與 Scheduled 頁；登入、密碼、授權按鈕永遠由本人做。

## 確認清單（產完念給使用者）

每項一行：`檔名｜關鍵內容一句｜✅／要改`。例：

```
config.json｜主旨前綴【信箱報告】、收件人 me@example.edu.tw、唯讀｜
分類規則.md｜3 條業務線、12 個階段、21 個對接對象、急件＝有期限或來自主管｜
網頁排程指示.md｜平日 08:00／14:00 兩場、已開啟貼標籤、報告寄給本人｜
```
