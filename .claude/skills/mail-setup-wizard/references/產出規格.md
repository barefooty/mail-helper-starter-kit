# 產出規格（訪談後要長出的每個檔案）

> 所有檔案用繁體中文（使用者指定別的語言就照他的）。範例假資料一律不得進入產出。

## 1. `我的工作脈絡/工作脈絡.md`（人看的）

```
# ○○的工作脈絡（信箱小幫手用）
> 最後更新：YYYY-MM-DD｜來源：訪談＋對接對象清單.xlsx＋專案階段表.xlsx

## 我是誰
職稱／單位／工作一句話／角色原型（A–E，可複數）

## 信箱
掃描信箱／單人或共用（共用列分工）／報告收件人／報告時間

## 業務線與階段
每條線一張表：階段｜大約時間｜該收到什麼｜來自誰｜最容易出事的點

## 對接對象
表：單位｜聯絡人｜email 網域｜所屬業務線｜習慣／注意｜各階段目前狀態（未填寫「未填」）

## 信的優先序
最先看／一句帶過／急件定義

## 授權邊界
唯讀｜貼標籤（清單）；選的版本

## 之後想補充
（留空，提示他怎麼補）
```

## 2. `我的工作脈絡/分類規則.md`（給 AI 的，會整段貼進 prompt）

```
## 分類規則
### 第一層：業務線
- 【業務線 A】：寄件人屬於（對象清單）／主旨或內文含（關鍵字）→ 歸此線
- 對不上任何線 → 「其他」
### 第二層：階段（只在能判斷時標）
- 【業務線 A】／【階段 1】：關鍵字／時間窗
### 寄件人辨識
- email 或網域 → 對象名稱（單位）→ 業務線；附「習慣提醒」一句（有才寫）
### 優先序
1. 急件：（定義）
2. 還沒回覆且有期限
3. 還沒回覆
4. 已回覆／資訊
### 一句帶過
- （清單）
### 該來沒來（反向提醒）
- 【階段】【對象】應於【日期】前來信【內容】；本輪沒收到且已過期 → 報告「⏰ 該來沒來」區列出
### 人工判斷
- （使用者沒定義的情況，一律寫「請人工判斷」）
```

## 3. `設定/config.json`（進階版）

從 `進階版_雲端程式/config.example.json` 複製後填值，`_` 開頭的說明鍵保留：

| 鍵 | 來源 |
| :-- | :-- |
| report_subject_prefix | 第 7 題（預設【信箱報告】；提醒不可再改） |
| sender_name | 第 1 題（預設「信箱小幫手」） |
| track_keywords | 第 8 題提醒的手動待辦標籤名（預設 ["待處理"]） |
| auto_labels | 第 8 題選 2 才 enabled=true，labels 填「前綴/類別」全新名稱 |
| allowed_recipients | 第 2、7 題 |
| overlap_minutes / default_days | 維持 15 / 5 |

## 4. `設定/report_template.html`（進階版）

從 `進階版_雲端程式/report_template.template.html` 複製。模板的 `{{}}` 佔位分兩類：

| 設定時就填（精靈負責） | 執行時每輪填（跑報告的 AI 負責，**保留不動**） |
| :-- | :-- |
| `{{頁首色}}` `{{分隔線色}}` `{{警示色}}`（第 7 題 preset，色碼見 `風格preset.md`） | `{{日期（週X）場次}}` `{{起訖}}` `{{今日/本週}}` `{{今日／本週}}` |
| `{{工作區名稱}}`（單人＝「○○的信箱」）`{{追蹤標籤名}}` `{{追蹤關鍵字}}` `{{寄件顯示名稱}}` `{{報告名稱}}`（＝主旨前綴） | |
| `{{標籤原則說明…}}`（唯讀版／白名單版）`{{特殊類型區塊標題…}}`（有反向提醒＝「⏰ 該來沒來」，沒有就整區刪） | |

配色鐵則：頁首色＋警示紅，其餘灰階。

## 5. `設定/routine-prompt.md`（進階版）

從 `進階版_雲端程式/routine-prompt.template.md` 填所有【】；「【分類規則】」整段用 `分類規則.md` 內容取代；「【時間與場次】」依第 7 題；cron 換算 UTC 寫在檔頭。

## 5b. `設定/進階版_上傳包/`（進階版）

`gmail_triage.py` 只讀**跟自己同一層**的 `config.json`，雲端 routine 也是在 repo 根目錄執行，所以要上傳的檔案必須平放。產完第 3～5 項後，把下列檔案複製進這個資料夾（不建子資料夾）：

| 來源 | 複製成 |
| :-- | :-- |
| `進階版_雲端程式/gmail_triage.py`、`.gitignore`、`SKILL.md` | 同名 |
| `設定/config.json`、`設定/report_template.html`、`設定/routine-prompt.md` | 同名 |

**不放**：`.env`、任何含 token 的檔案、`我的工作脈絡/` 的 Excel 與 `工作脈絡.md`（分類規則已寫進 routine-prompt.md）。每次重產設定都要同步更新上傳包，並提醒使用者重新上傳。

## 6. `設定/網頁排程指示.md`（簡易版）

從 `簡易版_網頁排程/網頁排程指示.template.md` 填所有【】，產出的檔案**不得殘留任何【】**：

| 佔位 | 來源 |
| :-- | :-- |
| 信箱主人／單位、信箱地址 | 第 1、2 題 |
| 貼標籤相關段落（「已開啟貼標籤才保留」） | 第 8 題選「貼標籤」就保留並去掉提示字；選「完全唯讀」就整段刪掉，「這次要看哪些信」改用時間窗寫法 |
| 標籤清單 | 固定有 `小幫手/已整理`、`小幫手/急件`；每條業務線一個 `小幫手/<業務線名>` |
| 報告怎麼送 | 第 7 題：寄給本人（填收件人與主旨前綴）或不寄信、直接看排程的執行紀錄 |
| 時間與場次、時間窗的 N | 第 7 題；一天多場時，每場各一個排程，指示相同、只差場次說明 |
| 分類規則 | `分類規則.md` 全文 |
| 使用者的處理原則 | 第 6 題與使用者提過的原則；沒有就寫「沒把握就寫請人工判斷」 |

網頁排程在雲端執行，讀不到起始包資料夾。所以指示必須自成一體，不能寫「見某某檔案」。

## 7. `設定/安裝檢查清單.md`

依版本列「使用者本人要做的步驟」，每步三欄：做什麼｜怎麼確認做對了｜卡住時看哪裡。簡易版對應 `簡易版_網頁排程/安裝手冊.md` 步驟 1、3、4，並加一列說明上層標籤「小幫手」會自動出現；進階版對應 `進階版_雲端程式/安裝手冊.md` 步驟 1、3、5（上傳 `設定/進階版_上傳包/`）、6、7。

## 確認清單（產完念給使用者）

每項一行：`檔名｜關鍵內容一句｜✅／要改`。例：

```
config.json｜主旨前綴【信箱報告】、收件人 me@example.edu.tw、唯讀｜
分類規則.md｜3 條業務線、12 個階段、21 個對接對象、急件＝有期限或來自主管｜
網頁排程指示.md｜平日 08:00／14:00 兩場、已開啟貼標籤、報告寄給本人｜
```
