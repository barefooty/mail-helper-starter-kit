# 信箱小幫手 安裝手冊（保母級，照順序做就好）

> 預估時間：全新安裝約 40–60 分鐘（多數是一次性設定）。
> 全程只需要瀏覽器＋一台裝有 Python 3 的電腦（只在步驟 3 取授權時用到一次）。

## 開始前的三個必備條件

1. **自己的 Claude 帳號**（Pro 以上，能使用 claude.ai/code 的 routines 功能）。
   ⚠️ **私人信箱絕對不要用共用/別人的 Claude 帳號跑**——信箱內容會出現在執行帳號的對話紀錄裡，用誰的帳號＝給誰看信箱。
2. **自己的 GitHub 帳號**（免費版即可，github.com 註冊）。程式碼會放在**私人（Private）repo**，只有你看得到。
3. **要掃描的信箱是 Google 帳號**（Gmail 或學校/公司的 Google Workspace 信箱。經實測 NYCU 信箱可用；其他機構若在步驟 3 被「貴機構的管理員」字樣擋下，代表該機構封鎖自建應用程式，請改用個人 Gmail 或洽詢資訊單位）。

另外請知悉：routine 每天執行會消耗你自己 Claude 訂閱的用量；雲端環境變數**未加密**，能編輯該環境的人看得到你的憑證——所以一切都要放在自己的帳號下。

## 步驟 1｜建立 Google Cloud OAuth 憑證（一次性，約 15 分鐘）

全程用**要掃描的那個信箱**登入 https://console.cloud.google.com ：

1. 上方專案選單 →「新增專案」→ 名稱 `mail-triage` → 建立並切換過去。
2. 「API 和服務」→「程式庫」→ 搜尋 `Gmail API` → 啟用。
3. OAuth 同意畫面（新版介面叫「Google Auth Platform」）：使用者類型「**外部**」；應用程式名稱 `mail triage`；支援電子郵件填自己；儲存。
   ⚠️ **務必把發布狀態改成「正式版」**（「發布應用程式」按鈕）——停在「測試中」的話授權 **7 天就失效**，每週都要重弄。發布後不需通過 Google 驗證，授權時多一個警告畫面而已。
4. 「憑證」→「建立憑證」→「OAuth 用戶端 ID」→ 類型「**電腦版應用程式**」→ 建立後記下**用戶端 ID**與**用戶端密碼**。
   ⚠️ 憑證是自己的，**不要跟同事共用**同一組 client secret。

## 步驟 2｜先跑訪談，產出設定（建議最先做）

把起始包資料夾拖進 Claude（Cowork 或 Claude Code），說「**開始建置**」，回答 8 題並選路線 1。精靈會在 `設定/` 產出：

- `config.json`、`report_template.html`、`routine-prompt.md`
- `路線1_上傳包/`：要放上 GitHub 的全部檔案（程式＋設定已放在同一層）
- `安裝檢查清單.md`：你本人要做的步驟

這一步不需要信箱權限，可以先做完再回頭做步驟 1。

## 步驟 3｜取得 refresh token（在電腦跑一次）

在 `路線1_雲端完整版/` 資料夾開終端機執行：

```bash
python get_refresh_token.py --client-id "<步驟1的用戶端ID>" --client-secret "<步驟1的用戶端密碼>" --hint <你的信箱>
```

瀏覽器自動開啟 → 登入**要掃描的信箱** → 出現「Google 尚未驗證這個應用程式」→ 點「進階」→「前往 mail triage（不安全）」→ 允許。終端機會印出 `GMAIL_REFRESH_TOKEN=...`，先抄起來（注意保密，這串等於信箱的鑰匙）。

## 步驟 4｜確認設定

打開 `設定/安裝檢查清單.md`，確認步驟 2 精靈念給你的內容都正確。要改就對 Claude 說「補充：…」，它會重產設定與上傳包。

## 步驟 5｜推上自己的 GitHub 私人 repo

**不會用 git 的最簡做法（網頁拖拉）**：

1. 登入 github.com →右上「＋」→「New repository」→ 名稱 `mail-triage` → 選 **Private** → Create。
2. 進入 repo 頁 →「uploading an existing file」→ 把 `設定/路線1_上傳包/` 裡的檔案全部拖進去（程式與 config.json 必須在同一層，上傳包已幫你排好） → Commit changes。
   ⚠️ **絕對不要上傳 `.env`、`client_secret.json`、或任何含 token 的檔案**（模板附的 `.gitignore` 會幫會用 git 的人擋，網頁拖拉要自己注意）。

會用 git 的人：`git init` → commit → 推上自己的 private repo 即可。

## 步驟 6｜建立雲端 routine

1. 用**自己的 Claude 帳號**開 https://claude.ai/code → Routines → 新增。
2. **Prompt**：貼上你的 `routine-prompt.md` 的「Prompt 全文」整段。
3. **Repository**：連接步驟 5 的私人 repo（首次要授權 Claude 的 GitHub App 存取該 repo）。
4. **排程**：照你要的時間設 cron（**UTC**＝台灣時間減 8 小時；模板檔開頭有範例）。
5. **環境變數**（值不要加引號）：
   ```
   GMAIL_ADDRESS=<你的信箱>
   GMAIL_CLIENT_ID=<步驟1>
   GMAIL_CLIENT_SECRET=<步驟1>
   GMAIL_REFRESH_TOKEN=<步驟3>
   ```
6. **Network access 改 Custom**，加入（預設清單保留）：`gmail.googleapis.com`、`oauth2.googleapis.com`。

## 步驟 7｜測試

1. routine 頁面按 **Run now**。
2. 檢查報告收件人有沒有收到報告信（第一輪會抓近 `default_days` 天的信，量會比較大是正常的）。
3. 到信箱確認：信件仍是**未讀**、標籤沒有被動過（若你有啟用自動標籤，確認只貼了白名單標籤）。
4. 不滿意就改 prompt（routine 頁面鉛筆圖示）再 Run now。滿意後確認排程 Active，完工。

## 日常維護速查

| 狀況 | 處理 |
| --- | --- |
| 報告沒寄來 | routine 頁面看 Runs 記錄；排定時間後 10–30 分鐘內寄達都算正常（平台有延遲）；可 Run now 補發 |
| 停用/恢復 | routine 的 Active 開關（長假前關掉，回來再開） |
| token 失效（報告寫「換取 access token 失敗」） | 重跑步驟 3，新 token 更新到 routine 環境變數 |
| 改分類規則/收件人/時間 | 改 routine prompt（＋收件人要同步 config.json 的 allowed_recipients → 重新上傳 GitHub） |
| 不想用了 | 關 routine ＋ 到 https://myaccount.google.com/permissions 移除「mail triage」授權 |
