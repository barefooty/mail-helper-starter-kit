一、它會幫你做什麼、不會做什麼

會做（每天固定時間，例如 8:00 與 14:00）

  • 看新進的信，含垃圾信匣裡疑似漏掉的
  • 依你的工作分類：哪個專案、哪個階段、誰寄的、急不急
  • 寄一封摘要報告給你：還沒回的排前面、附一句建議、待辦追蹤
  • 提醒「該來沒來」：時間到了還沒收到的名單或文件
  • 你允許的話，在 Gmail 幫信貼上「它自己的」標籤（限路線 1）

不會做（永遠不會）

  • 替你回信、寄信給任何人
  • 動你手動貼的標籤、標已讀、刪信、移動信件
  • 把信件內容傳給你以外的人

二、三步建置

  1. 把整個資料夾拖進 ClaudeCowork 或 Claude Code 都可以。Claude 主動說「這是信箱小幫手起始包，準備好就說『開始建置』」。
  2. 說「開始建置」，回答 8 題（約 5 分鐘）每題有選項，也可以自己講；第 4、5 題可以用兩張 Excel 代替口述。Claude 把產出的檔案逐項念給你確認。
  3. 照它給的安裝檢查清單連信箱、設排程跑第一輪、看報告，不滿意就說「補充：…」再跑。收到第一封【信箱報告】。
訪談與產出設定完全不需要信箱權限。連信箱是安裝步驟，由你本人操作。

三、要準備的兩張 Excel（先填幾列就好）

在 我的工作脈絡/ 裡，每張都有範例列與「填寫說明」分頁。範例列的備註寫著「範例，請刪除」，填自己的資料後把它刪掉。

對接對象清單.xlsx

欄位填什麼小幫手拿來做什麼
單位、聯絡人跟你往來的人或單位報告卡片顯示「誰寄的」
email對方的信箱或網域認出寄件人，歸到對的專案
所屬業務線要跟《專案階段表》的業務線名稱一致第一層分類
習慣／注意你希望被提醒的一句話（來信要 CC 某人、常漏附件、常用私人信箱寄）報告卡片加一句提醒
階段N_…可改成你自己的階段名；填該對象目前狀態，不填也可以追蹤進度、該來沒來

專案階段表.xlsx

欄位填什麼小幫手拿來做什麼
業務線、週期工作的大分類與週期（學期制、年度制、專案制、常態）第一層分類
階段順序、階段名稱、大約時間這條線會經過的階段第二層分類
這階段會收到什麼信、來自誰名單、核銷單據、成績…「該來沒來」提醒
最容易出事的點你最常踩的雷該階段信件的提醒語
這兩張表只在你的電腦使用。email 只用來辨識寄件人，習慣欄只用來加提醒。不要把學生個資放進來。

四、訪談會問什麼

#問題答案會變成
1你是誰、工作主要在做什麼報告寄件名、助理的自我介紹
2掃哪個信箱、一人用還是多人共用收件人、工作區數
3手上有哪幾條業務線、各自週期第一層分類
4每條線的階段、該收到什麼可用 Excel第二層分類、該來沒來提醒
5誰會寄信來、對接對象與習慣可用 Excel寄件人辨識、習慣提醒
6哪些信最想先看、哪些一句帶過、急件怎麼定義優先序規則
7報告多久寄、幾點、寄給誰、什麼風格排程、收件人、配色
8授權邊界：唯讀／貼標籤／擬草稿安全設定（預設完全唯讀）
＋要貼標籤嗎？電腦常開嗎？路線 1 或 3

沒講到的分類邏輯，小幫手一律寫「請人工判斷」，不會自己補。

六、路線 1 安裝步驟（雲端完整版）

需要：自己的 Claude 帳號（Pro 以上）、自己的 GitHub 帳號（免費版）、要掃描的 Google 信箱、一台有 Python 3 的電腦（只在步驟 3 用一次）。完整細節見 路線1_雲端完整版/安裝手冊.md。

  1. Google Cloud 建 OAuth 憑證用要掃描的信箱登入 console.cloud.google.com：新增專案 → 啟用 Gmail API → OAuth 同意畫面（外部、發布為正式版）→ 建「電腦版應用程式」憑證。拿到用戶端 ID 與用戶端密碼；發布狀態顯示「正式版」（停在測試中，授權 7 天就失效）。
  2. 訪談產出設定就是第二節的三步，精靈已幫你做完。設定/ 裡有 config.json、routine-prompt.md、report_template.html 與 路線1_上傳包/。
  3. 取得 refresh token在 路線1_雲端完整版/ 開終端機跑 get_refresh_token.py，瀏覽器登入要掃描的信箱、允許。終端機印出 GMAIL_REFRESH_TOKEN=…，抄起來，這串等於信箱鑰匙。
  4. 推上自己的 GitHub 私人 repogithub.com 新增 repository，選 Private，把 設定/路線1_上傳包/ 裡的檔案全部拖上去（程式與設定已排在同一層）。repo 顯示 Private；沒有上傳 .env 或任何含 token 的檔案。
  5. 建雲端 routineclaude.ai/code → Routines → 新增：貼 routine-prompt.md 的「Prompt 全文」、連接 repo、設 cron（UTC＝台灣時間減 8）、填四個環境變數、Network access 加 gmail.googleapis.com 與 oauth2.googleapis.com。routine 頁面顯示 Active。
  6. 測試按 Run now。收到報告；信箱裡的信仍未讀、標籤沒被動（若啟用自動標籤，只多了白名單標籤）。
  7. 不滿意就改對 Claude 說「補充：…」，改完重新上傳 GitHub＋更新 routine prompt。第二次報告符合預期。
第一次多半卡在步驟 1，Google 的介面常改版。卡住時把畫面截圖給 Claude，它會對照手冊指路。

七、路線 3 安裝步驟（桌面輕量版）實測中

需要：自己的 Claude 帳號（Pro 以上）、Claude 桌面 app、要掃描的 Google 信箱。限制先講清楚：電腦與 Claude app 要開著才會跑；標籤不會貼到信上。

  1. 在 Claude 連接 GmailClaude 桌面 app → 設定 → 連接器 → Gmail → 用要掃描的信箱登入、允許。連接器清單裡 Gmail 顯示已連接。
  2. 跑一次唯讀測試開 Cowork，工作資料夾選這個起始包，對它說「照 設定/桌面排程prompt.md 用唯讀模式跑一輪，不要寄信」。報告/ 多一個 HTML；信仍未讀、標籤沒動。
  3. 設桌面排程Claude 桌面 app → 排程任務 → 新增：工作資料夾＝起始包、貼 prompt 全文、設時間。到時間 報告/ 有新檔（若設了寄出，收件匣收到報告）。
這條路線依 Claude 官方文件設計，尚未在真實環境跑過。卡住請回報，實測通過後這個標記會拿掉。

八、之後怎麼補充、怎麼關掉

想做什麼怎麼做
窗口換人、新增對象改 對接對象清單.xlsx，對 Claude 說「重新讀工作脈絡」；或直接說「補充：○○的窗口換成王小姐」
新增階段、改時間改 專案階段表.xlsx，說「重新讀工作脈絡」
改急件定義、改優先序說「以後廠商報價信算急件」，它只改分類規則
換路線說「換成路線 1」或「換成路線 3」，訪談答案沿用
路線 1 改完規則要重新上傳 GitHub＋更新 routine prompt（Claude 會提醒）
報告沒寄來路線 1：routine 頁面看 Runs，可 Run now 補發。路線 3：電腦或 app 沒開，開起來手動跑一次即可
不想用了路線 1：關 routine＋到 myaccount.google.com/permissions 移除授權。路線 3：刪排程任務＋設定裡中斷 Gmail

九、安全與隱私

用自己的帳號

自己的 Claude 帳號、自己的信箱、自己的 GitHub。共用帳號跑＝把信箱給共用帳號的每個人看。

憑證是鑰匙

路線 1 的 refresh token 等於信箱鑰匙，只放自己的私人 repo 與 routine 環境變數，不要跟同事共用。

資料夾不外傳

我的工作脈絡/ 與 設定/ 是你的工作筆記與聯絡資料。要分享起始包給別人，先把這兩個資料夾清空。

預設最保守

唯讀、不貼標籤、不擬草稿；你明確開才開。永遠沒有「自動寄出回信」這個選項。
